# Free Traveler — UI/UX Plan

- **Document ID:** UIUX-TRAVEL-001
- **기반 문서:** `docs/01_PRD.md.md`(PRD-TRAVEL-001), `docs/02_SRS_BASELINE.md.md`(SRS-TRAVEL-001), `docs/PROJECT_SCOPE.md`(SCOPE-TRAVEL-001), `docs/03_UI_COVERAGE_ANALYSIS.md`(UICOV-TRAVEL-001)
- **디자인 참고:** `design-reference/vendor/airbnb/DESIGN-airbnb.md` — 레이아웃 밀도·타이포 위계·단일 액센트 컬러 운용 방식만 참고하며, Airbnb의 색상 값(#ff385c 등)·폰트명(Airbnb Cereal)·로고·상표 요소는 사용하지 않는다.

### 1-5. Header / Footer (5개 화면 공통)

**Header**
- 좌측: Free Traveler 워드마크(로고 아이콘 없이 텍스트 워드마크, 코랄 포인트 1글자 또는 밑줄)
- 중앙/우측: 메인(`/`), 여행 준비(`/travel-tools`), 동행 찾기(`/mates`), 대표 소개(`/about`) 내비게이션 링크
- 우측 끝: 계정 진입점(`/account`) — 비로그인 시 "로그인", 로그인 시 닉네임 아바타
- Desktop 높이 72px, Mobile은 56px + 햄버거 메뉴로 내비게이션 축약(대응: REQ-FUNC-064, 065)
- 모바일 메뉴 열림 상태는 Modal 시트로 표시, `Esc`/바깥 클릭으로 닫힘

**Footer**
- 3열(Desktop) → 1열(Mobile) 링크 그룹: 서비스(여행지/여행 준비/동행/안전정보), 회사(대표 소개, 문의), 정책(이용약관, 개인정보처리방침, 동행 안전수칙, 콘텐츠 면책 안내 — REQ-FUNC-080)
- 하단 legal band: 저작권 문구, 외부 출처 고지("항공·호텔 정보는 외부 사이트로 연결되며 예약을 대행하지 않습니다")
- Footer는 흰 배경 + hairline 상단 구분선으로 처리(카드 그림자 없음)

### 1-6. 접근성·상호작용 공통 규칙

- 모든 인터랙티브 요소의 최소 터치 영역은 **44×44px** 이상(REQ-NF-023~025).
- 키보드 포커스는 `color.focus-ring`(네이비) 3px outline으로 코랄 CTA와 시각적으로 구분되게 표시하며, `outline-offset: 2px`를 적용해 텍스트와 겹치지 않게 한다.
- Drawer/Modal은 열릴 때 포커스를 내부 첫 상호작용 요소로 이동시키고 닫힐 때 트리거 요소로 복귀시킨다(Focus trap).
- 색상만으로 상태를 구분하지 않고 아이콘 또는 텍스트 라벨을 함께 표기한다(안전 경보 단계, 모집 상태 배지 등).
- 폼 오류는 필드와 `aria-describedby`로 연결하고, 에러 텍스트는 `color.error`로 표시한다.

## 2. 콘텐츠 밀도·Section 배치 공통 규칙

- 모든 화면은 Header–Section(들)–Footer 순서를 지키며, Section은 목적이 분명한 순서로 배열한다.
- SCR-001, SCR-002는 7개 Section, SCR-003, SCR-004는 6개 Section을 기본으로 하며 SCR-005는 역할별 탭 구조로 별도 설계한다.
- Desktop 콘텐츠 최대 폭 1200~1280px, Section 상하 여백 64~96px. Mobile Section 상하 여백 40~64px, Card는 1열.
- Hero는 1440px 화면에서 뷰포트 전체 높이를 차지하지 않으며, 다음 Section의 상단이 첫 화면에 일부 보이도록 높이를 제한한다(Desktop Hero 높이 목표: 520~600px, 뷰포트 900px대 기준 다음 Section 100px 이상 노출).
- 각 Section은 제목 + 1~3문장 설명 + 실제 콘텐츠(카드/폼/목록) 또는 명확한 CTA로 구성한다.
- Hero, Card Grid, 좌우 분할, Chip 목록, 3단계 안내, CTA Banner를 교차 사용하고 동일 Screen 안에서 같은 형식의 Card Grid를 3회 이상 반복하지 않는다.
- Lorem ipsum, "준비 중", "정보 확인 필요" 같은 자리표시자 문구와 의미 없는 빈 카드·과도한 여백을 두지 않는다.
- 데이터가 없는 목록형 Section도 "왜 비어 있는지 + 이용 방법 + 다음 행동 CTA" 3요소를 갖춘 Empty State로 대체하며 빈 화면처럼 보이지 않게 한다.
- 모든 제목·설명은 자연스러운 한국어 완성 문장으로 작성하고, 사진에는 실제 장소를 설명하는 alt 텍스트(예: "노을이 지는 발리 울루와투 절벽 사원")를 붙인다.

**Drawer/Modal**
- 여행지 상세 Drawer: 소개, 핵심 명소 5개↑, 추천 시기, 1일/3일 일정, 예산, 교통, 음식 3개↑, 에티켓, 출처·수정일, 즐겨찾기, 공유, (해외) 안전정보 보기 버튼 → 안전정보 Drawer로 전환. (REQ-FUNC-004, 005, 006, 009, 068, 069)
- 안전정보 Drawer: 8개 카테고리, 경보 단계 상단 텍스트, 국가/지역 범위, 출처·최종 확인일, stale 경고, 외교부 링크(새 탭). (REQ-FUNC-047~054)

**Desktop(1440px):** Hero 높이 약 560px(다음 Section 상단 노출), Card Grid는 6열 중 3열×2행 또는 6열 1행, 최대 폭 1240px.
**Mobile(390px):** Hero는 검색창+CTA만 세로 배치, Card Grid는 가로 스크롤 캐러셀 또는 1열 스택, Chip Section은 가로 스크롤.

**상태**
- Loading: Card Grid 스켈레톤(회색 블록, 텍스트 자리 표시 없이 형태만).
- Success: 위 표 기준 콘텐츠 표시.
- Empty: Section 6(동행글)만 데이터 유무에 따라 Empty State 분기, 나머지 Section은 정적 시드 데이터로 항상 채워짐(REQ-FUNC-008).
- Error: 여행지/안전정보 로드 실패 시 Section 단위 인라인 오류("목록을 불러오지 못했습니다" + 다시 시도) — REQ-FUNC-078.
- Unauthorized: 해당 없음(전체 공개 화면).
