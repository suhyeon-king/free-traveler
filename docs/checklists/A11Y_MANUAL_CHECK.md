# A11Y_MANUAL_CHECK — 키보드·스크린리더 수동 점검 (MANUAL-A11Y-KEYBOARD)

- **Requirement:** REQ-NF-025
- **Scope:** SCR-001~005 (`/`, `/about`, `/travel-tools`, `/mates`, `/account`)

## 이 문서의 성격

`TASKS/TASK-MANUAL-A11Y-KEYBOARD.md`가 정의한 이 Task는 **설계상 자동화로 대체할 수
없는 사람의 실제 브라우저 점검**이다(키보드만으로 조작, 스크린리더 음성 안내 확인).
Claude Code는 실제 사람처럼 키보드로 브라우저를 조작하거나 스크린리더 음성을 들을 수
없으므로, 아래 "자동 사전 점검" 절은 **Playwright로 키보드 이벤트(Tab/Shift+Tab/
Enter/화살표)를 프로그래밍으로 보내 관찰한 결과**다. 포커스 이동 순서·포커스 링 유무·
명백한 키보드 트랩 여부까지는 이 방식으로 확인할 수 있지만, 다음은 **확인하지
못했다**:

- 스크린리더(NVDA/VoiceOver 등) 실제 음성 출력이 의미상 올바른지
- 포커스 링의 실제 시각적 대비·가시성(사람 눈으로 보는 판단)
- 사람이 처음 접했을 때의 조작 난이도·직관성

**따라서 이 Task는 아래 자동 사전 점검만으로 DONE 처리하지 않는다.** 사람이 실제
브라우저(가능하면 스크린리더 포함)로 아래 "사람 확인 필요" 항목을 마저 확인한 뒤,
이 문서의 결과 표를 업데이트하고 Task Status를 DONE으로 바꿔야 한다.

## 자동 사전 점검 결과 (Playwright, 2026-09-19 실행)

방법: 각 Route에 접속해 `Tab`을 반복해 누르며 `document.activeElement`의 태그·접근
가능한 텍스트·포커스 스타일(outline/box-shadow)을 기록. `/travel-tools`는 추가로
탭 전환(라디오 그룹 + 화살표 키)도 확인.

### 자동 점검에서 발견한 항목

1. **Header 로고 링크("Free Traveler")에 커스텀 포커스 링 클래스(`FOCUS_RING_CLASS_NAME`)가 빠져 있음** — 다른 모든 내비게이션 링크는 `src/lib/a11y.ts`의 공통 포커스 링 스타일을 쓰는데, 로고 링크(`src/components/shared/Header.tsx`)만 브라우저 기본 outline으로 대체된다. 기능적으로 키보드 접근은 가능하지만 시각적 일관성이 깨진다. `SHR-HEADER-FOOTER`(이미 DONE, 이 Task Expected File 밖)의 수정이 필요해 이 Task에서 직접 고치지 않았다 — 별도 확인 후 처리 필요.
2. **모달/Drawer의 Escape 닫기는 코드상 구현되어 있음을 확인**(`src/components/shared/Modal.tsx`, `Drawer.tsx` 모두 `keydown`에서 `Escape` 처리) — 다만 실제 열어서 Escape로 닫히는지는 로그인 세션이 필요한 흐름(신고 Modal 등)이라 이번 자동 점검에서는 실행하지 못했다(사람 확인 필요).
3. **SCR-001 여행지/안전정보 Card는 Tab으로 도달은 되지만, Enter를 눌러도 상세 Drawer가 열리지 않는다** — `PAGE-SCR001`의 알려진 기존 제한사항(W05 Browser Checkpoint에서 이미 보고됨: "여행지/안전정보 카드 클릭 시 Drawer 미연동")과 동일한 원인으로, 이 Task에서 새로 발견된 문제는 아니다.

- [ ] Timeline·Gallery·CountryChips 섹션을 스크린리더로 들었을 때 이해 가능한 순서인가
